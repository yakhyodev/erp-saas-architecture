# ADR FIN-002 — Immutable double-entry accounting
Status: PROPOSED
Date: 2026-10-11

## Muammo
Moliya yozuvlari balanslangan, qayta tekshiriladigan va tuzatish tarixi saqlanadigan bo‘lishi kerak.

## Variantlar
1. Mutable balance-only model.
2. Double-entry immutable journal + derived balances.
3. External accounting-only engine.

## Taklif etilgan qaror
Har bir posted journal uchun debit=credit; journal header/lines atomik; posted yozuv o‘zgarmaydi; reversal va corrective posting orqali tuzatiladi. Source event idempotency va accounting-period controls majburiy.

## Sabab
Audit, reconciliation, financial reporting va ishonchlilik.

## Xavflar
Posting qoidalarining murakkabligi, rounding, ko‘p valyuta va performance.

## Ta'sir
Sales, Purchase, Inventory, Finance, Database, Security, Reporting. Approval kutilmoqda.

## Cross-module posting proposal — AR-005 / AR-008 / MR-06 (2026-10-11)

**Status remains PROPOSED.** This supplements the original immutable double-entry proposal; it is not an approval.

### Problem and options
An order, dispatch, invoice, payment or return may emit repeated events, while stock, AR and GL must not double-post. Options: (A) generic document event drives all effects (rejected proposal: ambiguous/double effects); (B) typed source facts, local atomic posting and durable inbox/outbox (preferred PROPOSED); (C) synchronous multi-domain transaction (OPEN pending Backend/Database review).

### Proposed contract
| Source fact | Stock | Finance GL / AR |
|---|---|---|
| Order confirmed | Reservation only, no physical movement | No automatic GL/AR |
| Dispatch posted | Inventory physical debit once | Cost/valuation recognition trigger OPEN |
| Invoice posted | No stock movement | Finance AR/revenue/tax, subject to jurisdiction and recognition policy OPEN |
| Settled payment | None | Cash/bank and AR allocation once |
| Return posted | Inventory accepted stock once | Finance valuation/credit note separate, policy OPEN |
| Reversal | Compensating Inventory movement if originally posted | Linked immutable Finance reversal only if original journal exists |

Uniqueness proposal: `(tenant_id, legal_entity_id, source_fact_id, journal_kind, accounting_policy_version)`. Transport event IDs are not economic identity. Same-key/same-payload replay returns stored result; changed payload conflicts. Finance commits journal lines and dedup marker atomically; outbox/inbox handles at-least-once events. Corrections preserve original posting references and audit. No assumption that Billing's chargeable transition equals GL posting.

### Risks, dependencies and OPEN choices
AR-004 FIN-001 provenance remains open; AR-005 trigger/valuation, AR-008 canonical Party/Payer/ReceivableOwner, tax jurisdiction, functional currency, fiscal periods, and cross-domain atomicity require approval. Sales owns order state, Inventory physical movement, Finance GL/AR, CRM Party candidate, Billing SaaS charges. No existing APPROVED business invariant is modified.

## Round 2 posting recognition and atomicity review — AR-005 / MR-06 / MR-07 (2026-10-12)

**Status remains PROPOSED.** Candidate typed facts: SalesConfirmed (no physical movement/GL by default), StockDispatchPosted (physical stock once, optional COGS/valuation), GoodsReceiptPosted (physical receipt once, optional GRNI), FinanceSalesInvoicePosted (AR/revenue/tax candidate, no stock), FinancePurchaseInvoicePosted (AP candidate, no stock), VerifiedPaymentSettled (cash/bank + allocation), CreditNotePosted (AR correction), ReturnStockPosted (physical return once), FinanceJournalReversed (linked compensation).

**Alternatives:** revenue at invoice vs performance/delivery; COGS at dispatch vs revenue matching; FIFO vs weighted average; AR at invoice vs milestone; AP at supplier invoice vs goods receipt accrual; tax point per jurisdiction; closed period adjustment vs authorized reopen. All **OPEN**, not implied by event names.

**Atomicity comparison:** A single Sales+Stock+GL ACID transaction offers immediate cross-domain consistency but tight coupling and enterprise-isolation constraints. B owner-local atomic transaction + outbox/inbox (preferred PROPOSED, Database §18) tolerates partial downstream failure with durable retry, reconciliation and visible pending state. No simultaneous assertion of both models as approved.

**Dedup contract:** economic unique key `(tenant_id, legal_entity_id, source_fact_id, journal_kind, accounting_policy_version)`, transport event ID distinct. Same-key same-payload replay returns stored result; different payload rejects. Journal header/lines, open-item effects, inbox outcome and outbox commit atomically within Finance. Reversal uses unique reversal fact and original journal link, prevents over-reversal; retry never creates duplicate journal. Missing source, late delivery, closed period and valuation-not-ready enter exception/reconciliation queue. Billing's independent SaaS charge key cannot be substituted for GL source identity.

**Dependencies:** Sales, Inventory, Finance, Database, Backend, Billing, Security, UX. FIN-001 provenance AR-004 remains OPEN.
