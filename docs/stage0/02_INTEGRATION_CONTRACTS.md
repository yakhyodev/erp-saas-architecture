2. Consumer: producer/type/version/scope validation → o‘z current service identity/domain policy → receipt yoki pending-work lookup (§1.4) → prerequisites tayyor bo‘lsa inbox/APPLIED receipt + semantic effect guard + owner state/ledger/result/outbox bitta owner transactionda. Failed effect transaction APPLIED claimni rollback qiladi. ACK effect commitdan keyin **yoki** §1.4dagi atomic durable deferred-work handoffdan keyin; pending ACK effect applied degani emas.
3. Relay kamida bir marta yetkazadi. Publish/ACK yo‘qolsa ayni event qayta yuboriladi; economic effect qaytalanmaydi. Global FIFO va exactly-once network delivery kafolati yo‘q.
4. Aggregate revision bo‘yicha ordering; legitimate not-yet-arrived original/valuation/predecessor `WAITING_DEPENDENCY`, durable resume §1.4 orqali. Stale event yangiroq holatni orqaga qaytarmaydi. Effective history kerak bo‘lgan Seat/charge consumer eski intervalni yo‘qotmaydi.
5. Transient failure bounded backoff/jitter; numeric retry budget/SLO **OPEN**. Exhausted retry operator ticketga o‘tadi, pending work yo‘qolmaydi va repairdan keyin resumable qoladi. Authorization rejection avtomatik transient retry emas.
6. Reconciliation original fact→outbox→inbox→effect→projectionni tekshiradi. Hech qachon boshqa owner ledgeriga to‘g‘ridan-to‘g‘ri fix SQL yozilmaydi; mavjud occurrence retry yoki yangi authorized correction command ishlatiladi.

Monthly partition detach yoki schema upgrade economic guard’ini yo‘qotmasin; nonpartitioned guard candidate. **Archive retention PITR rollback isboti emas**: earlier restore targetdan keyingi receipt/revoke holati backupda yo‘q bo‘lishi mumkin. **C02** quarantine/resume §1.5 majburiy; local stable IDs missing external effect yoki current deny evidence’ni avtomatik tiklamaydi.

### 1.4 C07 — WAITING_DEPENDENCY liveness va ACK

`RECEIVED → WAITING_DEPENDENCY → READY → APPLYING → APPLIED` / explicit `QUARANTINED` — consumer-owned proposed state machine. Immutable event/body/full SourceOccurrenceRef, dependency refs, retry/lease generation va disposition durable receipt’da. PENDING holat semantic APPLIED effect slotni **iste’mol qilmaydi**; same event yoki yangi envelope lookup pending workni resume qiladi, terminal no-op emas. Outcome projection `pending`/reasonni ko‘rsatadi.

State har **planned consumer effect-slot** uchun: valid raw meter ingest `sample_persist=APPLIED` bo‘lishi mumkin, lekin unresolved monetary `attribution/charge=WAITING_DEPENDENCY` alohida work/guard. Ingest receipt duplicate no-op pending ratingni processed deb yopmaydi. Command source ACCEPTED va downstream effect APPLIED ham alohida records; bir stage ACK keyingi stagelar applied degani emas.

Prerequisite signal + scheduled sweep + owner-port reconciliation lost wakeupdan himoya qiladi; timing/backoff/budget owner config **OPEN**, finite transient retry exhaustion durable operator work qoldiradi. Valid original kelgach current service auth/fingerprint/prerequisites rechecked, worker versioned lease oladi; effect + guard + APPLIED receipt + outbox atomik. Stale lease ACK/finalize qila olmaydi. Parallel same event/re-envelope bitta pending semantic workga bind, eventually bitta applied effect.

ACK ikki ruxsatli yo‘l: (a) effect transaction committed; (b) event receipt+dependency state+durable deferred-work/lease/retry obligation atomik committed. Handoff ishlatilmasa pending broker retry/no-ACK. Deferred ACK effect-applied claim emas; crash-after-pending, restart-after-prerequisite, crash-after-effect-before-ACK ham same ref bilan tiklanadi. Expected liveness: prerequisite verified mavjud, service policy allowed va work scheduler available bo‘lganda effect oxir-oqibat bir marta APPLIED yoki explicit actionable unresolved disposition; silent permanent processed/no-effect yo‘q. F-C07A…C, IG-04/09 va S1-04/06.

- **Payload:** document type/canonical ID/logical lineage, transition/source revision/occurrence, source Company/Branch, actual metric quantity/unit, server effective time, import-origin marker, original link. Resource uchun unique meter sample/interval va measured quantity.
- **Mapping:** Billing accepted account/legal link va effective policy bilan actual eligible componentni resolve qiladi; source eventdagi amount/Wallet client authority emas. - **Transaction:** ingest inbox/usage dedup owner-local; rating ready bo‘lganda actual charge/immutable liability+price snapshot/ledger/summary/outbox atomik. Failureda source biznes fact saqlanadi, Billing pending/exception ko‘rinadi.
- **Replay/correction:** yangi event ID, policy version yoki closed-month transport retry qayta debit emas. Cancellation before trigger no charge; after charge refund faqat signed policy. Correction source/policy/original charge bilan yangi bounded delta; old ledger re-rate UPDATE yo‘q.
- **Negative period:** actual debit durable balance `>=0`dan `<0`ga tushganda BILL-013 selected anniversary-clamp candidate. Real one-calendar-month/no estimated limit `APPROVED`; rearm/expiry restriction va late correction `OPEN`. Calendar/month clockni rollout bilan default tasdiqlab bo‘lmaydi.
